# AGENTS.md — working on OpenCycle

Read this first. It tells an AI agent (or a new human contributor) where the truth lives, how to rebuild, and what not to break.

## The one-paragraph summary

OpenCycle is a DIY GPS bike computer. **Everything is generated from source files**: the enclosure from `cad/params.py` + `cad/model.py`, the PCB from `pcb/design.py`, the viewer assets from both. Never hand-edit generated outputs (`pcb/opencycle.kicad_pcb`, `viewer/meshes.json`, `viewer/pcb.json`, `viewer/pcb_*.png`). Change the source, then run `tools/build_all.sh`.

## Sources of truth

| Topic | File | Notes |
|---|---|---|
| Enclosure dimensions | `cad/params.py` | Coordinate system documented at the top. Body is 86 × 52 × 16 mm. |
| Enclosure geometry | `cad/model.py` | Case variants: standard, aero, rugged. |
| Mechanical fit | `cad/check_fit.py` | Must print `OK` for all variants after any change. |
| Parts, nets, placement | `pcb/design.py` | One `part(...)` call per component. Keep-outs for battery and speaker live here too. |
| MCU pin choice | `pcb/pinmap.json` | Generated by `assign_pins.py`; overrides the defaults in `design.py`. |
| Screen UI | `viewer/ui/screens.js` | Reference renderer for the 240 × 400 1-bit display. The firmware will port this. |
| Decisions / open questions | `docs/DECISIONS.md` | Append to it; don't rewrite history. |

## Coordinate systems (important)

- **CAD** (mm): x = width (0..52), y = height (0 = bottom edge with USB-C, 86 = top), z = depth (0 = back face, 16 = front glass). The Garmin mount boss is at negative z.
- **KiCad board** (mm): x right, **y down**, viewed from the front (display side = F.Cu). Board outline x 3..49, y 3..83.
- Conversion: `cad_x = kicad_x`, `cad_y = 86 - kicad_y`. PCB back face at `cad_z = 10`, front at `11`.
- Back-side (B.Cu) parts hang toward the battery. Anything under the battery pocket must be ≤ 0.3 mm tall (nothing is allowed there).

## Rebuild

```bash
./tools/build_all.sh          # full pipeline, ~5–8 min (router passes dominate)
```

Individual steps are in `docs/PCB.md` and `docs/CAD.md`. Required tools: see `docs/SETUP.md`.

## Rules for changes

1. **Mechanical changes:** edit `cad/params.py`, run `cad/check_fit.py`, then regenerate `viewer/meshes.json` with `tools/export_meshes.py`.
2. **Board changes:** edit `pcb/design.py` → `build_pcb.py` → `check_place.py` must say `placement OK` → route → `finish.py` → read `pcb/drc_report.txt`.
3. If a board part moves, check the matching enclosure feature (button plungers, USB cut-out, speaker pocket, standoffs) and update `cad/params.py`.
4. **UI changes:** keep to what a 1-bit memory LCD can show — no greys except via `d.dither()`, no blur, no alpha. Test at 1:1 with the "Actual size" toggle in the viewer.
5. **Public repo:** never commit personal information, credentials, or local absolute paths. Commit messages carry no AI co-author trailers.
6. **Honesty about status:** anything not verified (routing, DRC, datasheet pinouts, part availability) must be marked as such in docs. The board is **not for fabrication** until `pcb/README_NOT_FOR_FAB.md` is resolved and removed.
